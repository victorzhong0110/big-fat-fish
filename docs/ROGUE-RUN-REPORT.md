## 3. 关键实验数据（**以机器字段为准**）

### 3.1 两档机器人对照（**同一 build，同种子 1000/1037/1074，同 250 游戏秒上限**）

| build | smart（会读对症） | good（按稀有度挑） |
|---|---|---|
| **保底机制之前**（`src/systems/draft.js` 改动前的 mtime 之前） | 3 局：**1 次真通关**（wave20 `victory`, hp9/6）、到第 20 波 **3/3**、avg **21.5** 波 | 2 局：**0 通关**、到第 20 波 **0/2**、avg **9.5** 波、死第 **12 / 7** 波 |
| **保底机制之后** | 3 局：`(seed1000,20,over,hp0,kill546/595)` `(seed1037,22,timeout,hp6,672/733)` `(seed1074,20,victory,hp9,658/662)` | ✅ **1 局补跑成功**（冻结快照上跑，端口 8917）：`(seed1000,12,over,hp0,kill17/199)` |

> ★ **同种子直接对照（保底后的 build，同一份 dist）**：
> **seed 1000 —— smart 打到第 20 波（546 杀 / 595 生成，击杀率 0.92）；good 死在第 12 波（17 杀 / 199 生成，击杀率 0.09，怪堆满身）**。
> 也就是说：同一个种子下，**不会读对症的那一档是字面意义上「被怪淹没」，会读对症的那一档在清场**。

> **口径说明（重要）**：上一行两组数字**出自同一份 build**——
> `src/systems/draft.js`（手段保底）的 mtime 是 **20:22:23**，而 good 报告是 18:57、smart 报告是 20:09，**都在保底之前**。
> 所以「smart 有 1 次通关、good 0 次」**是同 build 的合法对照，结论成立**。
> 而**保底之后**只有 smart 的浏览器数据 + 离线对照（见 3.2），good 的浏览器数据**没有补上**。

### 3.2 机制纯度：它自己把代价写了下来（离线 3000 局，同 build）

| | 无保底 | 有保底（换收益最低的那张） |
|---|---|---|
| smart 最终倍率 | 2.271 | **2.425** |
| good 最终倍率 | 1.627 | **1.956** |
| smart 比 good 高（最终倍率） | 39.6% | **24.0%** |
| smart 有效 DPS 高 | 33.6% | **21.2%** |

它明确写了这是**取舍**：「**可玩性优先于机制的纯度** —— 一个『抽到就赢、抽不到就死』的机制，
对真人玩家来说不是难度，是抽奖。」

## 4. 这一轮真正有价值的三个技术成果

### 4.1 把「对症」从提示变成机制（§23）
克制 = 伤害 **×2.5**，判定接在**唯一的扣血入口**（子弹穿体 ⇒ 按被打的那只算）；
倍率曲线是**凸**的（`1 + 1.5 × 命中占比²`）⇒ 凑齐手段远比单张值钱；
四种手段的命中集合**互不重叠**（单一手段覆盖 8%–61% 血量，凑齐约九成）；
**深化也能给手段**（抽不到对症牌时有唯一出口）；
手段牌同时带伤害收益 ⇒「对症」与「强」不再二选一。

### 4.2 面板说人话（§25）
新纯模块 `src/systems/relicValue.js` ⇒ 每张候选牌显示「**伤害 +20%**」/「**不提高伤害**」，
转化型标「**（满层估计）**」不把理论值当保证。
并修掉一个**面板在撒谎**的口径 bug：「暴击率 +8%」在旧口径下收益算成 0 ⇒ 面板会说「不提高伤害」；
期望 DPS（含暴击期望）提到 `upgrades.js:20` 的 `expectedDps()`，覆盖度/抽卡估值/bot 评分**共用这一份**。

### 4.3 抽卡「手段保底」（§26）

**先量问题多大再改**：实测「旧行为下 **24.5%** 的第一章抽卡里一张手段牌都没有」⇒ 新行为 0.0%
⇒「这不是难度，是**机制被运气否掉**」。
实现（`src/systems/draft.js:78-93`）：候选里至少一张带手段的牌，
但**只保证看得见不保证拿得到**、**池里没有不强塞**、**换掉收益最低的那张**（随便换一张会让普通 DPS 掉 ~17%）。

### 4.4 面板不冤枉一张好牌（§27，第十二轮）
`relicValue()` 现在把**前提写出来**而不是换一个数：
- 有伤害收益 → 「伤害 +X%」
- **只给暴击伤害、手里没暴击率** → 「**暴击伤害 +70%（要配暴击率）**」
- 真的什么也不加 → 「不提高伤害」
- 转化型 → 「伤害 +X%（满层估计）」

它自己的验证：`vitest 343/343`（24 文件，新增 1 条「条件性收益不能被写成『不提高伤害』」）、
WebGL 134/134；**Canvas 本轮未跑，它自己标注「不能算验过」**。
本轮**只改文案、没改任何数值** ⟹ 第九~十一轮的实测数据继续有效。

## 7. 收尾：敌人形象换成 AI 模型的宠物（主 agent 改动）

用户要求：**不是商标（logo），是两个产品里的「虚拟形象（pet）」**。查证后落地：

| 阵营 | 来源 | 画法 | 配色 |
|---|---|---|---|
| **GPT 系** | **Codex Buddies**（OpenAI Codex 里的宠物） | 像素**小工人**：方块头 + visor 屏 + 帽檐 + 手臂 | 淡紫 `#A98CF0` |
| **Claude 系** | **Claude Buddy**（Claude Code 终端电子宠物，18 个物种） | 像素**小动物**：猫头鹰 / 水滴 / 企鹅 / 蘑菇 / 章鱼 / 小龙 / 蘑菇王 / 六角龙 | 陶土橙 `#D97757` |
| **合体** | —— | 终局 Boss：一只大 Dot 背上趴着像素蟹 | 两色 |

玩家仍是 **DeepSeek 的蓝色大肥鱼**（鲸鱼娘）⇒ 阵容 = 深海的蓝鲸 vs GPT 的工人 vs Claude 的宠物。

**为什么用像素网格画**：这两个 pet 本来就是像素风，而本项目是**零素材**游戏（所有图形运行时生成）
⇒ 用 16×16 的方格表画，改一个格子就能调造型；而且**圆润 vs 方块**两种轮廓天然分族，
**不依赖颜色**（色觉障碍也读得出阵营）。

**实现要点**
- 新增 `src/art/avatars.js`（纯逻辑，不 import Phaser）+ `src/art/graphics-probe.js`（把 Graphics 调用录成 SVG 的离屏渲染器，可单测）。
- `drawAvatar()` 的 API 与旧版**完全一致** ⇒ `textures.js` / `hud.js` / `legend.js` **一行都不用改**，替换完全收敛在一个文件里。
- 敌种**改名**与之对齐（贪嘴小鱼→快递小工、水母→猫头鹰、海葵→蘑菇、铁壳蟹→重装工兵…），因为"画成小工人却叫贪嘴小鱼"不自洽。
- 🔴 **加载时自检**：每个精灵的格子角点必须落在 8 格半径内 ⇒ **视觉大小 == 碰撞大小**。
  这条当场抓出 4 处越界（`cat` 的尾巴、`capybara` 的脚、`coder` 的笔记本、`heavy` 的手臂）—— 越界意味着**画得比判定圈大**，玩家会"看着没打中却被打死"。
- 敌种名同时进 `index.html` 的主菜单图例（`tests/legend.test.js` 会对手抄的名字与数据对账）。

**版权边界**：两个 pet 都是各自产品的**受版权保护的角色**。本作**不复制任何官方像素图 / 美术资源**，
只用代码**重新画一遍同类形体**（借鉴的是公开可见的造型规律），坐标与细节全部自定；
商标与角色版权归 OpenAI / Anthropic，本作不暗示任何授权、赞助或关联。详见 `NOTICE` 与 `DECISIONS-AVATARS.md` §3。

### 7.1 n=4 的对照结果（**两档首次在同一份评测器上重测**）

> ⚠️ **旧数据作废**：评测器（`bot.mjs` 的估值口径）在第九轮之后改过 ⇒ 旧对照组不是同一份代码跑出来的，不能比。
> 本次两档都在 `bot.mjs` 最后改动（19:37）之后重跑（两份报告均 23:59）⇒ **同一评测器版本，对照有效**。

| | smart（会读对症） | good（按稀有度挑） |
|---|---|---|
| 通关主线 | **1 / 4**（seed 1074，第 20 波 victory，HP 9/9） | **0 / 4** |
| 到达第 20 波 | **3 / 4** | **1 / 4** |
| 平均波次 | 20.3（17~23） | 18.8（15~22） |
| 死亡局 | 0（全是 timeout） | 1（seed 1074，第 15 波） |
| 末段覆盖度 | 0.95 / 2.03 / 2.42 / 1.04 | 1.21 / 4.57 / 0.91 / 2.05 |

**诚实判定**：
- ✅ **仍然分开的只有一件事**：「到达第 20 波」**3/4 vs 1/4**。
- 🔴 **通关率 1/4 vs 0/4 在 n=4 下不成立**（差一局，达不到显著）。
- 🔴 **平均波次 20.3 vs 18.8 差 1.5 波，但两档的区间大量重叠**（17~23 / 15~22）⇒ 差值落在方差里。
- 🔴 **两档共 8 局里 7 局是 `timeout`（撞 250 秒游戏时钟上限）** ⇒ 报告的"平均波次"是**被时钟截尾的深度**，不是死亡深度。

⇒ 与第九轮"两档彻底分开"的说法相比，**这轮的数据只支持一个弱得多的结论**：
**机制仍在，但优势收窄到"更常打到第 20 波"**。原因大概率是**抽卡「手段保底」**（两档都拿得到手段牌）
与**需求曲线重抬**共同稀释了差距 —— 这一点它自己也算过（离线分离度 34% → 21%）。
**下一次要 n≥8 才有资格谈通关率。**
