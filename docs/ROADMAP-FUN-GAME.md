# 大肥鱼 V2（Big Fat Fish）后续开发规划与 AI 协作指南

> **核心定位**：一款**玩 AI 圈黑话梗的轻松爽游**（DeepSeek 大肥鱼对战 ChatGPT、Claude、Grok 阵营）。
> **当前策略**：做减法、抓爽点。优先打磨 **10 分钟一局的短途爽游体验与画面打击感**，暂缓 40 分钟三海域长途远征和重度长线数值系统。

---

## 一、交给其他 AI 开发前必读的工程红线

任何接手开发的 AI 在修改代码前，必须严格遵守以下约束：

1. **逻辑与表现严格隔离**：
   - `src/v2/domain/` 与 `src/v2/engine/` 为纯确定性逻辑层，**禁止**引入 DOM、Canvas、浏览器 API 或非确定性 `Math.random()`。
   - 所有纯视觉特效（粒子、闪白、震屏、残影、台词气泡）全部放在 `src/v2/preview/` 中，通过**比对前后帧 `snapshot` 差异**来触发，不要污染 `tick.js` 的状态与重放校验。
2. **已锁定美术资源不可破坏**：
   - `public/art/characters/` 下的 12 个立绘受 `public/art/characters/approved-art.json` 和 `npm run test:v2:characters` 字节级校验保护，**禁止覆盖或重编码原图**。
   - 新增角色或状态图必须新增文件（如 `chatgpt.png`、`deepseek-hurt.png`），并在 `src/v2/preview/characters.js` 中注册。
3. **每次改动后的标准验收命令**：
   - 若新增或修改了 V2 公开函数导出或签名，先执行 `npm run sync:v2`。
   - 交付前必须通过：
     ```bash
     npm run check:v2   # TypeScript 类型检查 + V2 架构依赖检查
     npm test           # V2 单元测试（tests/v2）
     npm run build      # Vite 构建校验
     ```

## 二、分阶段开发路线图（4 个 Stage）

建议每次只让 AI 执行 **1 个 Stage**，完成验收后再推进下一阶段。

### Stage 1：视觉与手感救急（让画面瞬间像个游戏）

**对应 Issue**：#4（特效缺失）、#3（Grok 齐跳）、#10（Rocky 边缘闪烁）、#12（蒸馏虚影混淆）
**目标**：零外部美术依赖，纯靠渲染层和运动参数调整，把试玩画面从“原型 Demo”拉到“独立爽游”。

1. **轻量特效池与打击感（`src/v2/preview/view.js`）**
   - 在 `view.js` 内部维护定长对象池：`ParticlePool`（火花/碎裂粒子）、`ShockwavePool`（扩散冲击环）、`ScreenShake`（镜头微震），并缓存上一帧 `prevSnapshot`。
   - **子弹命中**：对比实体血量下降或弹体命中消失，在命中点生成 3–5 粒对应阵营色的短寿命火花。
   - **敌人/玩家受击**：触发 2 帧纯白受击闪白（使用离屏小 Canvas `globalCompositeOperation = 'source-atop'` 绘制白色剪影），叠加 1 帧挤压拉伸弹性缩放（如 `scale(1.15, 0.85)` 快速回弹），取代单纯的 `globalAlpha = 0.55`。
   - **敌人死亡**：实体从快照移除时，在其位置生成 6–8 粒阵营色碎裂消散粒子，避免瞬间消失。
   - **爆炸冲击环与轻震**：Grok 火箭及范围爆炸事件触发半径内扩散冲击环 + 轻度镜头震动。
   - **性能降级开关**：在设置面板增加“简化特效”开关，保障手机端浏览器流畅度。

2. **蒸馏虚影敌我区分（`src/v2/preview/characters.js` / `view.js`）**
   - 处理 `distilled_bot` 时不再直接调用原色 `drawCharacter(..., 'grok')`。
   - 改为使用离屏 Canvas 将其染成与主角 DeepSeek 一致的蓝紫色半透明能量剪影，并附带气泡尾迹，彻底消除“为什么我打出了敌人”的误解。

3. **运动表现 Bug 修复（`src/v2/domain/`）**
   - **Grok 齐跳打散（#3）**：在 `src/v2/domain/locomotion.js` 中，将 `hopPeriod` 改为基于实体 ID 哈希的错落周期（如 44–56 tick），并拉大 `phaseOffset` 分散度；贴地等待阶段可加极轻微的呼吸缩放。
   - **Rocky 边缘闪烁修复（#10）**：在 `movement.js` / `locomotion.js` 中，为 `visualFacing` 增加速度死区滞回（例如仅当 `|vx| > 12` 时才更新水平朝向，或直接朝向目标点），消除贴近地图边界与 leash 弧线时的帧级左右翻转。

**Stage 1 验收标准**：
- 战斗时能清晰看到命中火花、受击闪白+弹性反馈、死亡碎裂、爆炸冲击环。
- 一波 >= 8 只 Grok Bot 起跳明显错开；Rocky 在边界移动不闪烁；蒸馏虚影一眼能看出是友方派生。
- `npm run check:v2` 与 `npm test` 全绿。

---

### Stage 2：关键立绘补齐与角色状态表现

**对应 Issue**：#5（ChatGPT 龙尾立绘）、#13（受击等独立状态立绘）
**目标**：解决 `boss_gpt` 借用 Codex 图的违和感，提升主角和 Boss 的动画表现力。

1. **ChatGPT 本体立绘（#5）**
   - 新增资源：`public/art/characters/chatgpt.png`（透明底、大头 Q 版、右向 45° 三分之三侧、白发龙角龙尾特征，自绘风格与现有立绘对齐）。
   - 代码接线：在 `src/v2/preview/characters.js` 的 `CHARACTER_NAMES` 加入 `'chatgpt'`，将 `resolveCharacterModel` 中 `id === 'boss_gpt'` 的映射从 `'codex'` 改为 `'chatgpt'`，并同步登记到 `approved-art.json`。

2. **关键状态立绘分级接入（#13）**
   - 优先只为 **主角 `deepseek` 和 3 位 Boss（`claude`、`chatgpt`、`grok`）** 补充受击（`-hurt.png`）与攻击（`-attack.png`）状态图；普通杂兵继续沿用 Stage 1 的程序化闪白与弹性缩放，控制美术成本。
   - 扩展 `drawCharacter` 选图逻辑：按 `pose.hurt` / `pose.attacking` 优先查找对应状态图，若未提供则自动回退到基础静态图 + 程序化效果。

**Stage 2 验收标准**：
- ChatGPT Boss 拥有独立白发龙尾立绘，不再与 Codex 杂兵混淆。
- 主角与 Boss 受击/攻击时有明确换图表现，且 `test:v2:characters` 校验通过。

---

### Stage 3：海克斯爽池扩容与 AI 黑话梗演出

**对应 Issue**：#14（插件池扩容）、#6（有梗没好玩法）、#11（工作区文案）
**目标**：把 10 分钟短局打造成高潮迭起、让人会心一笑的肉鸽爽游。

1. **扩充“拿了立刻爽”的海克斯插件（#14）**
   - 在 `src/v2/content/catalogData.js` 与 `src/v2/content/handlers/plugins.js` 中新增 **12–15 个常见/进阶直给型插件**，参考《海克斯大乱斗》的即时反馈感：
     - 射速/攻速直给（如“Token 管够：射击间隔 -20%”）
     - 移速/机动直给（如“超频上下文：移速 +18% 且拾取吸附翻倍”）
     - 弹幕/爽感直给（如“并发请求：额外 +1 发弹道”“零延迟推理：冲刺冷却 -35%”“算力溢出：弹体体积 +30% 且穿透 +1”）
   - 评估并放宽现有硬顶：移速上限从 `1.8×` 适当抬高至 `2.2×`，最低射击间隔从 `0.05s` 放宽至 `0.035s`。

2. **落地 3 个强互动 AI 梗机制（#6）**
   - **ChatGPT · 重新生成**：Boss 重置阶段时，在场上生成两个发光地面回答区（“草稿 A / 草稿 B”），玩家踩中正确区域可直接打断回血并赋予 Boss 短暂易伤，将“纯机制回血”变成有参与感的互动博弈。
   - **DSH · 更新还是重置**：增加可见倒计时与状态提示气泡，触发“Reset！”时在主角周围爆发一圈清冷却能量波，强化爽感反馈。
   - **幻觉诱饵**：诱饵放出时带有假血条，头顶随机飘出一本正经胡说八道的短气泡台词（如“正在为您重新编译太平洋…”“已自动为您订阅 99 个上下文…”），强化喜剧效果。

3. **信标语义与状态调整（#11）**
   - 将 `src/v2/preview/view.js` 与 `host.js` 中的“占领”统一改为“**工作区**”；角色进入圈内推进进度时，在圈上或脚下显示明确的“**工作中**”状态。

**Stage 3 验收标准**：
- 局内三选一能高频刷出直观提升攻速、移速、弹幕量的爽感海克斯，10 分钟短局构筑成型快、爽感明显。
- 3 个核心梗具备明确视觉/交互反馈。

### Stage 4：信息架构改版与模式瘦身

**对应 Issue**：#2（元气骑士布局）、#9（出发模式改版）、#8（伙伴小剧情救助）、#7（技能树轻量化分枝）
**目标**：在核心玩法和特效已经好玩的前提下，精简外围入口与操作体验。

1. **《元气骑士》对标布局与世界锚定（#2）**
   - 修改 `v2.html`、`src/v2-preview.css`、`src/v2/preview/host.js`、`src/v2/preview/view.js`：
     - **首页极简化**：主路径只保留标题文案、大肥鱼立绘、“开始冒险”与“继续检查点”，其余入口收进底栏抽屉。
     - **脚下状态环 + 方向楔**：在 `view.js` 世界坐标中围绕主角脚下绘制外环（HP）与内环（护盾/技能就绪），环上方向楔指向当前目标或 Boss，靠近可交互物时在环旁显示短促的 `F` 提示。
     - **手机端操作簇**：左半屏移动摇杆，右半屏瞄准射击摇杆并贴合 MCP/技能/冲刺钮；可交互时同位替换为主交互钮。

2. **模式与养成轻量化（#9, #8, #7）**
   - **出发页收敛（#9）**：Free 教学首次真实通关后从主卡片隐藏（移入“更多”）；主入口收敛为 **剧情模式 / 讨伐模式（刷战利品） / 爬塔模式（无尽递增）**。
   - **伙伴小剧情救助（#8）**：将部分静默条件解锁改成局内遭遇虚弱伙伴时“分一口大白饭救助”的短对话演出。
   - **技能树轻量化分枝（#7）**：避免做成过于沉重的长线网，保留 2–3 条有明显取舍感的短分枝即可，让玩家每局都能快速感受到成长差异。

```text
本次任务仅执行 **Stage 1（视觉与手感救急）** 的全部内容：

3. 完成后请运行 `npm run check:v2`、`npm test` 和 `npm run build` 验证通过，并汇报改动文件列表与实测结果。
```
